# Operating Systems — Revision Notes

These notes were written for the StudyForge evaluation set and cover processes, scheduling,
synchronization, deadlocks and memory management.

## 1. Processes and Threads

A process is a program in execution. It has its own address space containing the code, data,
heap and stack, plus operating-system state kept in the process control block (PCB), such as the
program counter, CPU registers, open files and scheduling information. A process moves through the
states new, ready, running, waiting (blocked) and terminated.

A thread is the smallest unit of CPU scheduling. Threads of the same process share the code, data
and heap and open files, but each thread has its own stack, registers and program counter. Creating
a thread is cheaper than creating a process, and switching between threads of the same process is
faster because the address space does not change.

A context switch saves the state of the running process into its PCB and restores the state of
the next process. Context switches are pure overhead: no useful user work happens during them, and
they also pollute CPU caches and the TLB.

## 2. CPU Scheduling

First-Come First-Served (FCFS) runs processes in arrival order. It is simple but suffers from the
convoy effect, where short processes wait behind one long CPU-bound process.

Shortest Job First (SJF) picks the process with the smallest next CPU burst and is provably optimal
for minimising average waiting time, but it requires predicting burst lengths, usually with an
exponential average of previous bursts, and it can starve long jobs. Its preemptive version is
called Shortest Remaining Time First (SRTF).

Round Robin (RR) gives each process a fixed time quantum, typically 10 to 100 milliseconds, and
moves it to the back of the ready queue when the quantum expires. If the quantum is too large RR
degenerates into FCFS; if it is too small, the system spends most of its time context switching.

Priority scheduling runs the highest-priority process first. Low-priority processes may starve, and
the standard fix is aging: gradually increasing the priority of processes that have waited a long
time. A multilevel feedback queue moves processes between queues of different priorities based on
their observed behaviour, favouring interactive, I/O-bound processes.

## 3. Synchronization

A race condition occurs when the outcome depends on the unpredictable order in which threads access
shared data. The code that accesses shared data is the critical section. A correct solution to the
critical-section problem must provide mutual exclusion, progress and bounded waiting.

Peterson's solution solves the problem for two processes in software using a turn variable and a
flag array, but it may fail on modern CPUs that reorder memory operations unless memory barriers are
used. Hardware support includes atomic instructions such as test-and-set and compare-and-swap.

A mutex lock allows one thread into the critical section at a time. A spinlock is a mutex that busy
waits; it is only efficient when locks are held for very short periods on multiprocessor systems.

A semaphore is an integer variable accessed only through two atomic operations, wait (P) and signal
(V). A counting semaphore controls access to a pool of identical resources, while a binary semaphore
behaves like a mutex. The classic producer-consumer (bounded-buffer) problem uses a mutex plus two
counting semaphores, one counting empty slots and one counting full slots.

A monitor is a high-level construct that bundles shared data with the procedures that operate on it
and guarantees that only one thread is active inside the monitor at a time; condition variables with
wait and signal let threads sleep until some condition holds.

## 4. Deadlocks

A deadlock is a situation in which a set of processes are all blocked, each waiting for a resource
held by another process in the set. Four conditions, known as the Coffman conditions, must hold
simultaneously for a deadlock to occur: mutual exclusion, hold and wait, no preemption, and circular
wait.

Deadlock prevention breaks at least one of the four conditions, for example by imposing a global
ordering on resources so that circular wait cannot happen. Deadlock avoidance requires advance
knowledge of maximum resource needs; the Banker's algorithm grants a request only if the system
remains in a safe state, meaning there exists some order in which every process can finish.
Deadlock detection lets deadlocks happen, periodically searches the resource-allocation graph for
cycles, and recovers by terminating processes or preempting resources. Many general-purpose
operating systems simply ignore deadlocks, an approach nicknamed the ostrich algorithm.

## 5. Memory Management

Logical (virtual) addresses generated by the CPU are translated into physical addresses by the
memory management unit (MMU). Contiguous allocation suffers from external fragmentation: free memory
is split into small holes that cannot satisfy a large request even though the total free space is
enough. Compaction can fix this but is expensive.

Paging divides physical memory into fixed-size frames and logical memory into pages of the same size,
eliminating external fragmentation, although internal fragmentation can still waste part of the last
page. A page table maps page numbers to frame numbers. Because each memory access would otherwise
need an extra access to the page table, CPUs cache recent translations in the translation lookaside
buffer (TLB), a small, fast associative memory. The effective access time depends heavily on the TLB
hit ratio.

Segmentation divides memory into variable-sized logical units such as code, stack and heap, which
matches the programmer's view but brings back external fragmentation.

## 6. Virtual Memory and Page Replacement

Virtual memory lets a process run even when only part of it is in physical memory. With demand
paging, a page is loaded only when it is first accessed; accessing a page that is not in memory
triggers a page fault, and the operating system loads the page from disk.

When no frame is free, a page-replacement algorithm chooses a victim. FIFO replaces the oldest page
and suffers from Belady's anomaly: giving it more frames can increase the number of page faults. The
optimal algorithm (OPT) replaces the page that will not be used for the longest time; it cannot be
implemented because it needs future knowledge, but it is the benchmark for other algorithms. Least
Recently Used (LRU) replaces the page not used for the longest time in the past and does not suffer
from Belady's anomaly. The clock (second-chance) algorithm approximates LRU cheaply with a reference
bit per frame.

Thrashing happens when a process does not have enough frames to hold its working set, so it spends
more time paging than executing. The working-set model and page-fault-frequency control are used to
allocate enough frames and prevent thrashing.
