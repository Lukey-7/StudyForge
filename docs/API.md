# StudyForge v2 — REST API

Base URL (local): `http://localhost:8080`. Interactive docs: `http://localhost:8080/docs` (Swagger UI, generated by FastAPI).

**Auth:** every endpoint except `/health` and `/pipelines` needs `Authorization: Bearer <supabase access token>`.
In local demo mode (`AUTH_MODE=dev`) the header is ignored and a fixed dev user is used.

Errors are JSON: `{"detail": "message"}` (for 422 validation errors `detail` is a list of `{loc, msg, type}`) with a meaningful status code
(401 bad token, 404 not found / not yours, 409 conflict, 413 too large, 422 validation, 502 bad model output, 503 AI unavailable).

## Health & catalogue

| Method | Path | Returns |
|---|---|---|
| GET | `/health` | `{status, db_backend, auth_mode, chroma_mode, llm_model, embedding_model, openai_fallback, ai_configured}` . `embedding_model` is the model that actually ran; `llm_model`/`embedding_model` are `null` when no API key is set |
| GET | `/pipelines` | `[{name, title, description, retrieval_strategy, default_params, counts}]` (16 items) |

## Home

| Method | Path | Returns |
|---|---|---|
| GET | `/me/overview` | `{notebooks[] (most recently updated first, with source_count/ready_count), totals{notebooks, sources, ready_sources, generations}, recent_generations[] (8, without output, with notebook_title), recent_chats[] (6, with notebook_title)}`. ## Notebooks

| Method | Path | Body | Returns |
|---|---|---|---|
| GET | `/notebooks` | – | `[Notebook + {source_count, ready_count}]` newest first |
| POST | `/notebooks` | `{title, description?}` | `201 Notebook` |
| GET | `/notebooks/{id}` | – | `Notebook` |
| PATCH | `/notebooks/{id}` | `{title?, description?}` | `Notebook` |
| DELETE | `/notebooks/{id}` | – | `204` (deletes sources, chunks, vectors, files, generations, chats) |

`Notebook = {id, user_id, title, description, sources_version, created_at, updated_at}`

## Sources (documents)

| Method | Path | Body | Returns |
|---|---|---|---|
| POST | `/notebooks/{id}/sources` | multipart `file` | `202 {source, duplicate:false}` or `200 {source, duplicate:true}` |
| POST | `/notebooks/{id}/sources/text` | `{title (1-200 chars), text (min 20 chars)}` | same as above (pasted notes) |
| GET | `/notebooks/{id}/sources` | – | `[Source]` |
| GET | `/sources/{source_id}` | – | `Source` — poll every ~2 s until `status` is `ready` or `failed` |
| GET | `/sources/{source_id}/chunks` | – | `[Chunk]` |
| POST | `/sources/{source_id}/retry` | – | `202 Source` |
| DELETE | `/sources/{source_id}` | – | `204` |

Allowed files: `.pdf .docx .txt .md .png .jpg .jpeg .webp .mp3 .wav .m4a .ogg .flac` (max 25 MB).

`Source = {id, notebook_id, file_name, file_type, mime_type, size_bytes, status, error_message, page_count, chunk_count, embedding_model, created_at, updated_at}`
`status ∈ uploaded → extracting → chunking → embedding → ready | failed`

`Chunk = {id, source_id, notebook_id, chunk_index, page, page_end, heading, text, token_count}`

## Generation (16 pipelines)

`POST /notebooks/{id}/generate/{pipeline_name}`

```json
{ "difficulty": "beginner|intermediate|advanced", "length": "short|medium|long",
  "focus_topic": "optional string", "source_ids": ["optional"], "force": false }
```

Returns a `Generation`:
```json
{ "id": "...", "notebook_id": "...", "pipeline_name": "quiz", "params": {...},
  "output": { ...pipeline-specific JSON..., "_meta": {"strategy": "...", "chunks_used": 12, "map_calls": 0} },
  "model": "gemini-3.8-flash", "latency_ms": 8123, "created_at": "...", "cached": false }
```
This call is synchronous and can take 10–90 s for big notebooks (map-reduce + free-tier rate limit).

`GET /notebooks/{id}/generations` → latest 50 generations, newest first (same shape without the `cached` flag).

## Retrieval debug

`POST /notebooks/{id}/search` `{query, mode: dense|bm25|hybrid|hybrid_mmr|hybrid_mmr_rerank, source_ids?, page_from?, page_to?}`
→ `{query, embedding_model, layers, citations[], context, context_tokens}`

`layers = {mode, dense?: [{id, score}], bm25?: [{id, score}], fused?: [{id, score}], mmr?: [chunk_id]}`. A layer is present only if the mode uses it.

## Chat (streaming)

`POST /notebooks/{id}/chat` `{message, session_id?, source_ids?}` → `text/event-stream`:

```
event: meta   data: {"session_id": "...", "rewritten_query": "...", "citations": [Citation]}
event: token  data: {"text": "partial answer "}        (many)
event: done   data: {"message_id": "...", "session_id": "...", "citations": [Citation actually used]}
event: error  data: {"message": "human readable"}
```
`Citation = {label: "S1", chunk_id, source_id, source_name, page, heading, snippet}` — the answer text contains `[S1]` markers.

The HTTP status is always 200 once streaming starts; failures arrive as an `error` event (if AI isn't configured, `error` comes first and no session is created).

Because the request is a POST with an auth header, the browser uses `fetch()` + a stream reader (not `EventSource`).

| Method | Path | Returns |
|---|---|---|
| GET | `/notebooks/{id}/chat/sessions` | `[{id, title, created_at, updated_at}]` |
| GET | `/chat/sessions/{sid}/messages` | `[{id, role, content, citations, rewritten_query, created_at}]` |
| DELETE | `/chat/sessions/{sid}` | `204` |
